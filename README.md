# 密码学实验 · C 语言实现（OpenSSL EVP）

三个经典密码学实验的完整 C 实现，共 833 行，直连 OpenSSL 3.x 的 EVP 高层接口。
每个实验都包含**反面验证**——不只是让算法跑通，还要验证它在什么情况下会失败。

| 实验 | 算法 | 源码 | 行数 |
|---|---|---|---|
| 1-1 对称密码 | AES-256-CBC | `src/aes_lab.c` | 337 |
| 1-2 非对称密码 | RSA-2048 + OAEP(SHA-256) | `src/rsa_lab.c` | 292 |
| 1-3 Hash | SHA-256 | `src/sha_lab.c` | 204 |

---

## 为什么值得看

不是"调用一下加密函数"的作业。三个文件里有几个刻意的设计选择：

**1. 密钥材料用 PBKDF2 确定性派生，而不是 `RAND_bytes`**

实验需要可复现——同一个种子每次必须得到同一组密钥，才能让别人复算出与报告一致的密文。
但直接把种子当密钥用太脆弱，所以走 `PBKDF2-HMAC-SHA256`、10 万轮迭代派生 32B 密钥 + 16B IV。
**确定性 + 不可直接反推**，两个需求同时满足。

**2. AES 做了雪崩效应实测**

把明文 `1F` 改成 `1E`（只翻 1 个比特），分别加密，统计两组密文的比特差异。
这是验证分组密码扩散层的直接方法——理论上应该接近 50% 的比特翻转。

**3. RSA 显式验证了明文长度上限**

`RSA-2048 + OAEP(SHA-256)` 单块能加密的上限是 `256 − 2×32 − 2 = 190` 字节。
代码对超长输入不吞掉，而是让 EVP 明确拒绝并打印原因——**用它来说明"非对称算法必须配合
分组或混合加密"这件事，而不是把它当成一个要绕过的 bug**。

**4. 篡改检测**

改 1 个字节的密文再解密，验证必然失败。这是完整性校验的实证，不是概念描述。

## 编译与运行

需要 OpenSSL 3.x 开发库。Windows 下用 MSVC：

```bat
cd src
build.bat                    :: 一键编译三个实验
aes_lab.exe                  :: 文件加解密 + 十六进制对比
aes_lab.exe hex 1F           :: 只做单块加密对比（雪崩效应）
rsa_lab.exe                  :: 生成密钥对 + 分块加解密 + 篡改验证
sha_lab.exe                  :: 摘要计算 + 1 比特篡改 + 定长性验证
```

Linux / macOS：

```bash
gcc -O2 -o aes_lab aes_lab.c -lcrypto
```

## 实现细节

**AES-256-CBC**：`EVP_EncryptInit_ex` / `EVP_EncryptUpdate` / `EVP_EncryptFinal_ex` 三件套，
PKCS#7 填充由 EVP 自动处理，解密时会校验填充合法性——填充错误能直接反映成解密失败，
这本身就是一层轻量的完整性信号（虽然不等价于 MAC）。

**RSA-2048-OAEP**：私钥 PEM 用种子派生的口令加密存储（`PEM_write_bio_PrivateKey` 带密码回调），
避免明文私钥落盘。OAEP 而非 PKCS#1 v1.5，是为了避开后者已知的填充预言问题。

**SHA-256**：内存摘要和文件摘要两条路径。文件走 4 KB 分块 `EVP_DigestUpdate`，
不把整个文件读进内存——这样任意大小的文件都能处理。
